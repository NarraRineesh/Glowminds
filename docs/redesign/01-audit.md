## Design direction (binding for tokens and components)

Narra: the product must not look generated by a template. Avoid generic indigo/purple-blue gradients, gradient text, glassmorphism, glowing blobs, sparkle or magic-wand motifs, emoji as icons, oversized rounding, and a hero plus a three-card grid. Aim for a restrained, intentional, product-crafted surface in the spirit of Linear, Stripe, and Notion:

- One confident accent. Neutrals do the rest. Success, warning, and danger stay semantic and rare.
- Strong type hierarchy (a few sizes, consistent weight). No `font-black` display headlines and no gradient-clipped words.
- Purposeful density. Real content, not decorative cards.
- Subtle 1px borders instead of heavy shadows, blurs, and radial washes.
- One icon set. Phosphor (already wrapped by `src/components/icons/AppIcon.jsx`) is that set. Do not add a second library, and do not keep Sparkle as the visual shorthand for “AI”.

This direction applies to the marketing site and the signed-in product. They share one token file and one component set. Stage 2 (below) is where tokens and primitives change. This stage does not restyle anything.

### Where the current UI violates that direction

| Pattern Narra ruled out | Where it shows up today |
| --- | --- |
| Radial glow / blob | `DashboardShell` fixed wash; `LandingHero` ellipse; `AboutPage`, `FeaturesPage`, `PricingPage` hero washes; `features/design-lab/tokens.css` shell background |
| Gradient text (`from-primary` to `emerald-400`, `bg-clip-text`) | `AboutPage`, `CareersPage`, `ContactPage`, `FeaturesPage`, `PricingPage` headlines and metric numbers |
| Gradient card fills | Landing exit CTA (`LandingPage`), About and Features closing cards, Learning plan header in `UpskillingSection` (`bg-gradient-to-br`) |
| Glass / backdrop blur | `DashboardTopbar`, `PublicHeader`, Features preview cards, Learning sticky mobile bar and stat chips |
| Sparkle motif | Sidebar upgrade CTA, credit chip, hero CTA, Apply Kit, interview hints, Settings billing, Learning empty actions. Icon name `sparkle` in `AppIcon.jsx`. Emoji `✨` maps to it |
| Emoji as icons | `AppIcon.jsx` `EMOJI_TO_NAME` still accepts emoji stored in Firestore or old configs (`📊`, `💼`, `✨`, `🔥`, …). Rendering must stay until those stored values are migrated, but new UI must not write or display emoji |
| Template grids | Landing “four steps” card row and a 3-column testimonial grid (`LandingPage`). Features page repeats the same hero-metric-card rhythm |
| Extra hues used as decoration | `--ai` cyan, `--profile` violet, emerald marketing highlights, amber stars, chart hexes `#22c55e` / `#f59e0b` / `#a855f7` / `#ef4444` in `AnalyticsSection.jsx` |

`LandingHero` itself is closer to the target than the inner pages: the highlight word is flat `text-primary`, not a gradient. The inner marketing pages and the dashboard wash are the louder surfaces.

### Token and component rules for stage 2

Implement these in `src/app-theme.css` and the primitives under `src/components/ui/` plus `packages/glowminds-resume/src/lib/ui/`. Do not invent a second theme in `features/design-lab/tokens.css`.

- **Accent.** Keep the current flat blue `#2563eb` as the single accent until Narra picks a different hue. Stop pairing it with emerald, cyan, or violet in the same composition. `--ai` and `--profile` become aliases of the accent or disappear from product chrome. Semantic `--success`, `--warning`, `--destructive` stay for status only.
- **Surfaces.** Flat `--background`, `--card`, `--muted`. No radial-gradient utility on shells or heroes. No `backdrop-blur` on chrome.
- **Borders.** `--border` at low contrast. Shadows limited to focus rings and overlays (dialogs, menus). Cards do not get colored glows.
- **Radius.** One scale from `--radius: 0.5rem`. Controls and cards use `rounded-md` or `rounded-lg`. `rounded-full` only for avatars, status dots, and the credits count if it stays a compact chip. Remove `rounded-2xl` decorative panels.
- **Type.** Outfit remains the UI face (already loaded). Weights 400 / 500 / 600. Page titles semibold, not black. Marketing and product use the same scale. JetBrains Mono only for numbers that must align (credits, prices, scores).
- **Icons.** Phosphor via `AppIcon` only. Replace decorative `sparkle` with a literal icon (file, briefcase, chat) or no icon. Keep `EMOJI_TO_NAME` as a read-path so old Firestore values do not render as raw emoji; do not add new emoji keys.
- **Marketing composition.** No centered hero plus three equal cards as the default section. Prefer a left-aligned title, one primary action, and a real product fragment (the existing resume or jobs mock can stay if it shows actual UI, not a gradient illustration). Testimonials, if kept, are a simple list, not a card grid.
- **Density.** Dashboard pages already aim at compact cards (`DashboardCard` header `py-2.5`). Do not inflate padding when restyling. Marketing sections can stay quieter without becoming sparse hero templates.

## Styling approach

- **Tailwind CSS v4** via `@tailwindcss/vite`. No `tailwind.config.js`. Theme is `@theme inline` in `src/app-theme.css`, imported by `src/index.css`. `@plugin "@tailwindcss/typography"`. `tw-animate-css`. `@source` includes `src` and `packages/glowminds-resume`.
- **Dark mode** is class + attribute: `[data-theme="dark"]` and `.dark`, set by `src/hooks/useTheme.jsx` (default **dark**, key `localStorage.theme`) and the blocking script in `index.html`.
- **CSS elsewhere:** `features/design-lab/tokens.css` (lab only), `features/dashboard/styles/AnalyticsCharts.module.scss`, `ScoreGauge.module.scss`, `packages/glowminds-resume/src/embed/host.css`, resume package `globals.css`. Product UI is otherwise utility classes.
- **Motion:** `framer-motion` on marketing sections and every dashboard route. Honor `prefers-reduced-motion` (already on `MotionConfig` and in `app-theme.css`). Do not add more entrance motion.
- **Charts:** `recharts` in Analytics and `features/admin/AdminCharts.jsx`.
- **Toasts:** `sonner` through `src/components/Toast.jsx` and `useAppStore.addToast`. Many screens also keep inline error strings. Pick the toast for transient failures when restyling; do not invent a third channel.
- **Fonts:** `index.html` loads Outfit, Inter, JetBrains Mono from Google Fonts, non-blocking. `--font-sans` is Outfit then Inter. Boot shell uses system-ui on purpose so first paint does not wait on fonts.

## Responsiveness and the Android WebView

Breakpoints are Tailwind defaults plus `useIsLg` (`src/hooks/useIsLg.js`) for a few layouts that swap in JS (applications kanban vs list, tool sidebars, public nav). Prefer CSS so a resize does not remount columns.

Known fragile spots:

- Dashboard is a locked `h-dvh` column. Resume embed height is `h-[min(100dvh,100%)]` and `max-md:h-[calc(100dvh-var(--dashboard-chrome,8rem))]` while the shell sets `--dashboard-chrome` to `7rem` or `0`. Easy to clip on Android.
- Topbar pads `safe-area-inset-top`. The scroll body pads `safe-area-inset-bottom`. The sidebar drawer and marketing sheet should be checked against the same insets.
- AI chat and resume are the only routes that scroll inside the panel. Other pages scroll the outlet. A restyle that adds a second sticky bar must subtract it from both.
- Applications: board at `lg`, a single status column below, with a sticky add bar. Do not drop the mobile column.
- Jobs filters and Learning’s sticky bottom bar compete with the home indicator.
- `capacitor.config.json`: `appId` `in.glowminds.app`, `server.url` `https://app.glowminds.in` (remote WebView, not the bundled `dist`), `androidScheme` https, splash 1800ms, background `#07090f`, no spinner. `allowNavigation` includes the marketing host, Firebase, and Google auth domains. `src/utils/nativeApp.js` detects `?app=android`, `source=android_app`, `android-app://` referrer, `Capacitor.isNativePlatform()`, and a Glowminds Android user agent.
- There is no in-repo Android layout to restyle. Web CSS is the mobile app. Do not run `cap sync` against a production URL as part of a visual PR.

## Accessibility

Already in place: skip link, `lang`, focus rings (`outline-ring`), `MotionConfig reducedMotion="user"`, reduced-motion CSS, some `aria-expanded` on sidebar groups, theme toggle label, public nav `aria-label`, form errors on login/signup, footer link `min-h-11`.

Issues a restyle should correct rather than copy:

- More than one `h1` on dashboard routes that also render `SectionHeader` or `PageTitle`. The skip link lands on `main`, which includes the sidebar, so “skip to content” does not skip navigation.
- `v2` `FilterBar` sets `role="tablist"` and `role="tab"` without `tabpanel`s or arrow-key behavior.
- `KpiCard` uses `role="button"` on a `div` when `onClick` is set. Name comes from the visible label only if the text is inside. Prefer `Button`.
- Icon-only destructive actions in profile entry rows and job cards need accessible names. Audit them per page in the feature stage.
- Analytics charts have no text alternative or table fallback. Admin charts neither.
- Collapsed sidebar tooltips are hover-oriented. Touch and keyboard need the visible label or an `aria-label` on the link (partially there via `tooltip` prop).
- Settings tab list hides the scrollbar and uses a custom `Toggle` that may not expose `switch` semantics. The imported `Switch` does.
- `BrandLogo` is often `alt=""` beside a wordmark. That is fine when the wordmark is visible. On small marketing headers the wordmark is hidden and the home link has `aria-label="Glowminds home"`. Keep that when the wordmark collapses.
- Contrast intent is documented in `app-theme.css` for primary and muted text. Do not lighten primary back to `#3b82f6` on white labels. Gradient text fails contrast by construction and goes away under the design direction.
- `theme-color` stays `#07090f` even in light mode, so Android chrome stays dark.
